# Agent trajectory benchmark

Issue #560 adds a benchmark for whole agent turns. The `agent_tool_call` scenario of the
[local-inference benchmark](local-inference-benchmark.md) only checks one probe answer. This
benchmark runs the agent loop from the user message to the final answer: tool call, result, next
call, answer. It also counts misroutes in both directions: answering when a tool was needed, and
calling a tool when none was needed.

It is the baseline for agent changes such as probe early stop and reasoning off (#563/#565),
instructions on the last turn (#567), family samplers (#571), report layout and history folding
(#573), and grammar-constrained tool calls (#575).

## What runs

The cases live in
[`benchmarks/agent-trajectory/trajectory-cases.json`](../benchmarks/agent-trajectory/trajectory-cases.json).
They are synthetic and deidentified (`Beispiel`/`Muster` patients, `synthetic-patient-560-*` IDs).
Each case declares:

- `scope`: `patient` (with the pre-loaded patient JSON the app injects) or `global`;
- optional earlier `history` turns and the `user_message`;
- `kind`: `tool` (needs at least one call) or `no_tool` (the answer is in the prompt or is general
  knowledge);
- `expected_calls`: tool name, required arguments and the canned `result` returned to the agent.
  `ordered: false` accepts the calls in any order;
- `answer`: facts the final answer must contain (`contains_all`, `contains_any`) and must not
  contain (`excludes`), plus a `reference_answer` that CI checks against them.

The runner calls the production loop (`agent::run_agent_turn`, which `run_agent_loop` also uses)
with a scripted tool executor instead of the database. The system prompt, probe, stop rule,
tool-call grammar, parser, history layout, history folding and answer generation are the code that
ships. Only tool dispatch is replaced. The system prompt uses the suite's fixed date
(`today`), so runs can be compared. The dedicated router model is not used; probes run on the
writing model.

## Metrics

Each run is scored on:

| Metric | Meaning |
| --- | --- |
| Sequence | Called tool names equal the expected ones (in order unless `ordered: false`) |
| Args | Expected calls made with all required arguments (subset match; strings match case-insensitively by containment) |
| Malformed/probe | Probes that opened a `<tool_call>` but produced no valid call of a scope tool |
| Misroute | Answered without a needed tool, or called a tool when none was needed |
| Grounding | Final answer passes all required-fact and forbidden-fact checks |
| Forbidden facts | Failed `excludes` checks |
| Iterations | Probes per turn (`MAX_ITERATIONS` = 8; hitting the limit fails the run) |
| Probe tokens | Tokens generated by the probes |

A run passes only if all of these pass. The result also keeps each probe's raw output, generated
tokens, parsed call, exact prompt token count, and whether the history was folded.

Metrics are reported per model family, labelled `<sampler family>/<chat family>` (for example
`Qwen/Native`, `Gemma4/Gemma4`, `GptOss/Harmony`), because the recent agent changes act per
family. One run loads one model; `report` merges several runs into one table.

## Run it

On Apple Silicon macOS, from `dokassist/src-tauri`, with a downloaded GGUF:

```sh
cargo run --release --features benchmark-harness,metal --bin agent-trajectory-benchmark -- run \
  --model /absolute/path/to/Qwen3-8B-Q4_K_M.gguf \
  --output ../../benchmark-results/agent-trajectory/qwen3-8b.json
```

Options:

- `--profile NAME`: inference profile (default `governed`, as shipped);
- `--repetitions N`: repeat every case (default 1);
- `--cases id1,id2`: run only these cases;
- `--skip-model-hash`: do not hash the GGUF (faster; the result then records no SHA-256).

The command prints one line per case and a per-family table, and writes the full JSON to
`--output`. `benchmark-results/` is ignored by Git.

To compare families, run each model and merge the results:

```sh
cargo run --release --features benchmark-harness,metal --bin agent-trajectory-benchmark -- report \
  ../../benchmark-results/agent-trajectory/qwen3-8b.json \
  ../../benchmark-results/agent-trajectory/gemma4.json
```

Check the fixture without a model:

```sh
cargo run --features benchmark-harness --bin agent-trajectory-benchmark -- validate
```

## CI

`cargo test --lib` runs the pure part: every case parses, expected tools exist in the case's scope,
each reference answer passes its checks, a perfect trajectory passes every case, and the scorer
detects misroutes, malformed calls, wrong arguments, swapped order, forbidden facts and the
iteration limit. No model is loaded in CI.

## Adding cases

Keep cases synthetic and German, with absolute dates (the prompt date is fixed). Canned results
should look like the real tool output (`tools.rs`). A `no_tool` case must be answerable from the
prompt or from general knowledge. Changing cases changes `suite_sha256` in the result; compare runs
only on the same suite.
